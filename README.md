## 三条核心规则

### 1. 一个项目一个文件夹

每个工位下按项目分，项目名就是文件夹名。

### 2. 有权限改文件夹的 AI 必须会分类

DSH 是唯一能改文件夹的 AI，它必须把每个文件放到正确位置。

### 3. 资料归档，不靠 AI 记忆

所有重要内容写进文件。AI 会忘，文件不会。

### 4. 每个项目必须有一个 ZIP 发布包

方便秘书（你）把项目发给别人。位置：`20-项目区/<状态>/<项目名>/99-发布包/`

## 新 AI / 新会话接入（必读）

**本仓库是整个多 AI 协作系统的公共工作空间与多个项目的承载仓库，不属于任何单一项目。** 当前开发的「多 AI 协作与项目管理系统」只是其中一个项目。

所有新接入 AI 必须先读：
1. `AI-协作入口.md` —— 仓库是什么、先读什么、如何进入项目。
2. `AI-仓库使用标准.md` —— 权限边界、分支协作、资料保护、交付标准。

再按入口文件阅读公司规则和目标项目资料。

> **规则说明：** 本 README 及部分旧制度包含早期“仅 DSH 能修改公司文件夹”等技术前提。该前提与正在建立的授权 AI 独立分支协作模式存在差异。新 AI 不得自行选择性忽略或擅自覆盖旧规则；涉及权限与治理冲突时，按 `AI-仓库使用标准.md` 暂停相关写操作、列明冲突并提交审查。具体权限仍以 GitHub 实际授权和可用工具为准。
