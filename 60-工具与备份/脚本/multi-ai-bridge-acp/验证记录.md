## 阶段 3 关键诊断（2026-11-16 18:55）—— 根因找到

### 问题：aidrop.sh 找不到目标 App 的输入框

表象：aidrop.sh 启动 DeepSeek 后，dump 到的 46 个节点全是 DSH 自己的
（package=io.github.ccch1mneyyy.dsh_app），没有 DeepSeek 的节点。

### 根因（三层）

1. ~~**DSH 抢回前台**~~（误判）：aidrop.sh 用 monkey 启动目标 App，但 DSH 正在运行
   （有 LauncherMist 悬浮窗机制），很快抢回 topResumedActivity。
2. **dump 抓的是 DSH**：DSH 是 proot 进程，通过 rootc 执行 uiautomator dump 时，
   抓到的是 DSH 自己所在的窗口层级，不是目标 App。
3. **DeepSeek 输入框对 uiautomator 部分不可见**：DeepSeek 是自绘/混合 UI，
   输入框节点 text/hint 都为空，只能靠 class 定位，但当前界面根本没 dump 到它。

### 这是「mCurrentFocus 误导」的升级版

之前记录的坑是「mCurrentFocus 会误导，要用 topResumedActivity」。
现在更深：**即使 topResumedActivity 对了，dump 到的 UI 也可能是 DSH 自己的**，
因为 DSH 有悬浮窗/LauncherMist，会抢焦点。

### 正确修复方向（下一轮）

1. **dump 前强制目标 App 前台**：用 `am start` 而不是 `monkey`，且启动后立即 dump 校验 package
2. **校验 dump 结果属于目标 App**：dump 后先查 package 是否含目标包名，不含就重试/报错
3. **隔离 DSH 悬浮窗**：dump 时让 DSH 的 LauncherMist 暂时隐藏，或用 screencap 代替 dump
4. **参考 Orca 的虚拟显示**：Orca 用虚拟显示避免抢占焦点，我们也可以考虑

## 阶段 3 根因完整版（2026-11-16 19:00）

### 完整根因链（三层叠加）

2. **修复后**：am start 能让 DeepSeek 保持前台，dump 抓到 46 个 DeepSeek 节点 ✅
3. **但输入框仍无法语义定位**：Compose 自绘 View，无 EditText/hint/content-desc

### 修复方案（分层，通用）

| 层 | 问题 | 修复 |
|---|---|---|
| 启动 | ~~monkey 让 DSH 抢前台~~（误判） | 改用 `am start`（无害，理由已修正） |
| 校验 | dump 抓到错误 package | dump 后校验 package 含目标包名 |
| 定位输入框 | Compose 自绘无语义 | **按坐标：屏幕底部 + 宽度>50% 的 View** |

1. 用 am start 而非 monkey
2. dump 后校验 package
3. 输入框定位改成「每个 App 自己的适配器」——Compose App 按坐标，传统 App 按 EditText/hint

## 阶段 3 关键架构认知（2026-11-16 19:10）

### aidrop.sh 的「解析」与「执行」必须分离

**踩坑**：试图在 aidrop.sh（Android sh，真机侧）里用 Python 解析坐标，
但真机侧没有 python3，find_input.py 也不在 /data/local/tmp。

**正确架构**：
- **Android 侧（rootc 执行）**：只做「执行」——dump、input tap、input text（纯 sh，无 Python）
- **proot 侧（Python，Ubuntu）**：做「解析」——读 XML、算坐标、编排流程（有 python3）

**分工**：
```
AppAgent（proot Python，负责解析和编排）
  ├── 调 rootc 执行：uiautomator dump → 拷 XML 回 proot
  ├── 用 find_input.py 解析 XML，算出输入框坐标
  └── 调 rootc 执行：input tap <坐标> / input text <文字>
```

**find_input.py 已经验证有效**：能精确定位 Compose 自绘输入框
（DeepSeek 输入框 = [66,2388][1206,2538]，宽1140高150留边距66）。

**find_input.py 定位策略**（三层）：
1. EditText class（传统 App）
2. text/hint/content-desc 提示文字（千问）
3. Compose 兜底：宽 0.5~0.98 屏宽 + 高 80~260px + y1 底部区域
