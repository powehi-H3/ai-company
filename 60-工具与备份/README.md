# 工具与备份区

本目录保存可复用工具源码、插件源码、备份包和部署/维护资料。**这里是资产区，不是所有 AI 都可直接执行的命令清单。**

## 目录结构

- `脚本/`：桥接适配器、事件流/关系引擎、心跳队列、流程引擎、项目管理脚本等源码。
- `插件-ai-company-web/`：AI 公司控制台 Cordis/React 插件源码及安装说明。
- `备份包/`：历史阶段快照和备份包；不得直接当作当前发布版。

## 使用前强制核验

1. 从 `SKILLS.md` 定位能力卡，再检查对应源码和依赖，不要仅凭索引状态执行。
2. 核对当前 Git 分支/commit、源码版本、设备路径、运行用户、App 包名、依赖版本和配置来源。
3. 区分“仓库存在源码”“设备已部署”“当前设备实测通过”三种状态；前者不能证明后两者。
4. 主体 DSH、DSH 分身、其他 AI 和 GitHub 连接器是不同权限主体；不得跨主体推定能力。
5. 对外发消息、修改资料、触发流程等操作必须明确目标和授权；先 dry-run/预览，再执行并留证。
6. 任何归档、删除、覆盖、批量移动操作均属高风险。尤其 `archive-project.sh` 在 S-03/S-04/S-07/S-34/S-35/S-36 修复并独立审查前，不得对真实项目执行；ACP/AppAgent 和 send_v2 的真实发送路径因 S-14/S-20 命令注入风险立即禁用。
7. 不得将仓库里的历史备份包覆盖到设备或当作当前部署包，除非完成版本、哈希和兼容性核验。

## 维护

新增工具必须同时补充 `SKILLS.md` 能力索引、工具说明、依赖/配置、适用节点、权限要求、dry-run 方式、测试命令、验证日期和已知限制。工具被替代时标记为遗留并保留迁移说明，不得静默删除仍被引用的源码。
