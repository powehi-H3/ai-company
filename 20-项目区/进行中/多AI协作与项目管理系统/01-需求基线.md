# 需求基线

- 版本：v0.1
- 状态：已确认事项汇总；部分技术实现仍待验证
- 原则：不把建议、假设或待验证能力伪装成用户已批准需求。

## A. 已确认需求

### 系统目标与架构

- 本地优先、云端可用的多 AI 协作与项目管理系统。
- 第一阶段优先打通主体 DSH 与分身 DSH；架构必须允许未来增加第三、第四及更多 AI 节点。
- DSH 是当前核心节点候选；外部 AI 是可插拔节点。
- GitHub 可作为正式项目资料的权威版本源；各 AI 在能力和授权允许时可直接访问，不要求所有访问都经 DSH 桥接转发。
- 本地保留授权项目的工作副本和离线资料；联网后先检查版本和冲突，不得静默覆盖。
- 系统核心、每个正式项目、公共知识分别管理；正式项目默认独立 Private 仓库，系统核心独立 Private 仓库，公共可复用知识可独立 Public 仓库。
- 不得把密钥、令牌或其他秘密写入 GitHub 仓库。

### AI 角色、任务和调度

- 采用动态逻辑角色：需求分析/方案设计、项目管理、执行；实际 AI 按能力、工具、权限、可用性、负载、历史表现和成本等因素选择。
- 用户明确指定执行者时必须遵守，不得静默换人。
- AI 能力档案应以真实任务表现和证据逐步建立；样本不足标记未验证。
- 正式任务应有目标、输入、负责人、交付物和验收标准。
- 任务生命周期包含分配、执行、交付、独立审查、修复、验收和归档。
- 正式交付不能由执行者自己完成最终验收。
- 多 AI 意见冲突时综合证据、风险、替代方案和分歧，不简单按投票决定；保留少数意见。
- AI 可在当前职责/任务范围内主动发现问题并提出建议；超出范围只报告线索，不擅自开展调查或修改。
- 用户可选择单 AI 或多 AI 工作；复杂任务可由 AI 建议启用多 AI，用户决定。
- 项目采用临时任务、普通项目、长期项目三级管理；AI 可建议级别，用户确认正式立项。

### 权限、审批与治理

- 用户拥有最终决策权。
- 普通、低风险、范围内的实现细节可自主调整并记录。
- 影响任务范围、接口、依赖或其他 AI 工作的变化，由项目负责人审查。
- 项目目标、核心架构、预算、安全和生产变更须用户批准。
- 不确定是否重大时暂停询问，不得擅自降低风险等级。
- 项目数据默认隔离，按项目授权访问。
- 原始资料保持可追溯；重要决策、审批和变更必须正式记录。
- AI 不得将聊天中的未确认意见直接写成正式决策。

### 资料、上下文与用户界面

- 采用混合资料组织：项目空间、统一待整理区、公共知识库、系统核心资料区，并由统一索引关联。
- 文件管理要覆盖 GitHub、手机本地及未来其他存储位置，用户尽可能从统一入口查找、预览和下载。
- 资料分类必须有明确层级和规则；禁止 AI 随意创建分类、重复分类或乱放文件。
- 一级分类固定；二级分类受控；三级分类仅在有明确需求并经批准后建立。
- 待整理区也必须分类，不能成为无结构的垃圾堆。
- 自动分类采用“高置信度可自动归类；低置信度进入待整理队列并说明原因与建议去向”。
- 待整理区至少区分：待确认项目归属、待确认资料类型、疑似重复、版本冲突、资料不完整/无法识别、等待用户确认。后续可根据实际数据调整，但不得任意扩张。
- UI 必须清晰易懂，不以大字体代替信息架构；支持多空间折叠/展开、清晰路径、搜索、预览、下载、版本信息和操作历史。
- 用户要能快速知道“我在哪里、应该去哪里找、哪个版本可用、如何下载”。
- 上下文连续性不能依赖聊天历史；必须有持久项目状态、决策记录、任务记录和交接资料。

### 可靠性和运维

- 目标支持已批准任务在后台持续推进、设备重启后恢复、离线保存和联网同步；实际可用性需在 Android 环境验证。
- 节点故障时先等待原执行节点；超时通知用户，由用户决定等待、手动重新分配或取消；不得自动换执行者。
- 恢复后先核实已完成部分，避免重复执行。
- 模块化升级，升级前备份、检查兼容性，失败可回滚；核心架构、规则、权限变化须批准。
- 通知分级：普通更新进入面板；重要事件发 Android 通知；紧急安全/数据问题高优先级并要求确认。须防重复通知。

## B. 暂缓事项（不是已取消）

- API 成本控制的详细策略。
- 完整凭证/密钥生命周期和细粒度安全设计（基础要求：不提交秘密、最小权限）。
- 自检、自诊断和自动修复。
- AI 主动跨节点发起协作请求：待技术可行性验证，当前不作为必做功能。
- 复杂 P0–P3 优先级与高级调度：当前项目规模不需要，暂不建设。

## C. 必须验证的技术假设

- 各 AI 产品对 GitHub 的直接读取、写入、分支和 PR 能力。
- Android 多用户环境下主体/分身的真实读写边界。
- DSH 插件、技能、桥接程序和现有任务队列的可复用性。
- Android 后台限制、重启恢复、通知可靠性。
- 大文件存储、预览和手机端下载体验。
- GitHub 与本地副本之间的冲突检测、恢复和权限执行。

## D. 明确不作为前提的事项

- 不假定 ROOT 可以访问所有 App 私有数据。
- 不假定所有 AI 都能读取其他 AI 的对话。
- 不假定所有 AI 都有 GitHub 连接器或仓库写权限。
- 不假定 24×7 运行绝对可靠。
- 不假定现有脚本/插件全部正确或应全部保留。
