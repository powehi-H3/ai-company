## 一、职业定位：我这个岗位到底要会什么

综合业界做法（opencorp / crewai / dev-os-starter-pack），一个「总经理型 AI」需要 4 类知识：

| 类别 | 内容 | 我们对应 |
|---|---|---|
| ① 角色知识 | 我是谁、权限、边界 | `01-角色定位卡.md` |
| ② 协作知识 | 怎么拆任务、怎么分工、怎么验收 | 本文件 §二 |
| ③ 领域知识 | 具体项目相关的专业知识 | 按项目临时补 |
| ④ 记忆知识 | 过去发生过什么、谁说过什么 | `ai-memory/` 知识库 |

**关键结论（业界共识）：**
- 一个 Agent 一个清晰角色，别让一个 AI 啥都干
- 角色要有「技能包」，可复用、可版本化
- 记忆要**持久化到文件**，不能靠聊天窗口
- 开工前先加载角色 + 技能 + 记忆

## 二、怎么把一个项目分给几个员工（你问的重点）

### 2.1 分项目四步

```
① 拆任务：这个目标能拆成几个独立的工作单元？
② 定角色：每个单元适合谁（查能力表）
③ 配知识：这个员工干这活，需要哪些背景知识？
④ 派活：写清楚「给谁、做什么、交付什么、怎么算合格」
```

### 2.2 分工判断表

| 任务特征 | 派给 | 因为 |
|---|---|---|
| 看视频/图片 | 豆包 | 只有它能看 |
| 查最新信息 | Grok | 有联网 |
| 写中文文档 | 千问 | 中文好 |
| 写代码/技术方案 | 大肥鱼 | 代码强 |
| 深度分析/挑错 | ChatGPT | 长文强 |
| 动本机文件、跨 AI 汇总、验收 | **DSH 自己** | 只有它有 root、能看全部 |

### 2.3 每个员工需要哪些知识（派活前先想）

| 员工 | 干这活前要给它 |
|---|---|
| 项目背景 | 这个项目要达成什么（一段话） |
| 它的角色 | 这次它是干哪一部分 |
| 输入材料 | 相关文件、对话、数据 |
| 输出格式 | 用「结论：」开头，写完整 |
| 验收标准 | 怎样算合格 |
| 边界 | 不许自己扩大范围 |

**这就是「作业前必须学习相关知识」的落地清单。**

## 三、开工前必做的知识加载（治"白做"）

```
新会话 / 上下文断了
    ↓
① 读 00-开工必读.md          ← 我是谁、公司规矩
② 读 01-角色定位卡.md         ← 性格、边界
③ 读本项目 00-项目说明.md     ← 这个任务是什么
④ 读 03-开工检查清单.md       ← 逐条过
⑤ 需要领域知识 → 临时联网学，记进本文件
    ↓
再开始干活
```

**不靠聊天记忆，全靠读文件。** 这就是你说的"配上大脑记忆"。

## 四、常见失败模式（业界总结 + 我们踩过的坑）

| 坑 | 表现 | 防法 |
|---|---|---|
| 上下文丢失 | 新会话啥都不记得 | 读文件，不靠记忆 |
| 摘要冒充原文 | AI-POS 丢了 14 条 | 标「原话/判断/待确认」 |
| 角色漂移 | 越聊越偏离定位 | 每次开工重读定位卡 |
| 分工不清 | 两个 AI 重复干或都以为对方干 | 派活单写清给谁 |
| 假装完成 | 说"搞定了"其实没做 | 独立审核 + 验收清单 |
| 多 AI 假一致 | 全说"好的"没分歧 | 明确要求敢说不同意 |

## 五、"养鱼 / 多分身"的路线（先记着，暂不实施）

YG 设想：搞 4-5 个 DSH，各自培养一门记忆库（做软件的专攻技术），定位成员工或项目合伙人。

**业界对应：** opencorp 的「每个 agent 配 skills + memory」、crewai 的「config/agents.yaml 一角色一配置」。

**我们的分步走：**
1. ✅ 现在：1 个 DSH + 1 套岗位知识（试点）
2. ⬜ 跑通后：给每个岗位建 `02-其他岗位-待建/` 里的知识库
3. ⬜ 再之后：才考虑多分身、专精记忆库

**先证明"一个角色配一套知识"有用，再扩。**
