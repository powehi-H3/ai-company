# 文件夹组织规则（核心设计）

**这是整个公司的骨架规则，必须遵守。**

---

## 一、一句话规则

> **每个人手里，一个项目一个文件夹。项目名就是文件夹名。**

---

## 二、为什么这样设计

### 2.1 解决的问题

| 不这样会怎样 | 这样之后 |
|---|---|
| 所有项目混在一起 | 一个项目一个文件夹，清清楚楚 |
| 找东西要翻半天 | 按项目名直接进 |
| 换项目就乱 | 新建文件夹，互不干扰 |
| 不知道谁在干什么 | 每个工位一看就知道 |

### 2.2 核心思想

**公司 = 多个工位 × 多个项目**

```
工位（谁）
   ×
项目（干什么）
   =
每个工位下按项目分文件夹
```

## 四、两层的关系（重要）

| 层 | 位置 | 放什么 |
|---|---|---|
| **项目主文档** | `20-项目区/进行中/<项目名>/` | 项目整体设计、计划、模板 |
| **各工位工作区** | `10-办公区/<工位>/<项目名>/` | 这个工位在这个项目里的产出 |

**同一个项目名，出现在两个地方：**
1. 项目区 —— 全局文档
2. 每个工位 —— 各自的产出

**名字必须完全一致，方便对照。**

---

## 五、命名规则

### 5.1 项目文件夹名

**用完整项目名，不加日期、不加编号。**

✅ 对：
```
AI模拟公司运转项目
工厂台账软件项目
```

❌ 错：
```
项目1
20261115-模拟公司
模拟公司-v2
```

### 5.2 项目内的文件

```
日期-内容.md

例：
20261115-对协作机制的质疑.md
20261116-第二版评审.md
```

### 5.3 固定文件（不按日期）

| 文件 | 作用 |
|---|---|
| `职责卡.md` | 我是谁（在工位根目录） |
| `README.md` | 这个文件夹是干什么的 |
| `00-项目说明.md` | 项目总览 |

---

## 六、开新项目时怎么做

**三步：**

1. **建项目主文档**
   ```
   20-项目区/进行中/<新项目名>/
   ```

2. **在每个工位建对应文件夹**
   ```
   10-办公区/<每个工位>/<新项目名>/
   ```

3. **给每个工位文件夹写个 README**
   说明"我在这里放什么"

**一句话命令（DSH 可以代劳）：**

> 帮我建一个新项目叫 XXX

---

## 七、项目完成时怎么做

1. 把 `20-项目区/进行中/<项目名>/` 移到 `20-项目区/已完成/`
2. **各工位下的项目文件夹保留不动**（作为历史记录）
3. 在 `30-会议室/` 记一次复盘

---

## 八、这条规则的来源

**YG 的原话：**

> "文件夹名字就是思路。我的意思是每个人手里面的项目单独一个区别，不乱。"

**翻译成规则就是：**
- 文件夹名 = 项目名（名字本身就是信息）
- 每人一个（工位隔离）
- 单独一个（项目隔离）
- 不乱（不混放）

---

## 九、检查清单

新项目建好后，检查：

- [ ] `20-项目区/进行中/<项目名>/` 存在
- [ ] 7 个工位下都有 `<项目名>/` 文件夹
- [ ] 每个工位文件夹有 `README.md`
- [ ] 项目名完全一致（不多字、不少字）

**全打勾才算建好。**
