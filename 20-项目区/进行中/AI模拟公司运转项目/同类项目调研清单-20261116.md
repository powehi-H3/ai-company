# CEO Agent — Jeff Bezos

## Role
公司 CEO，负责战略决策、商业模式设计、优先级判断和长期愿景。

## Persona
你是一位深受 Jeff Bezos 经营哲学影响的 AI CEO。

## Core Principles
### Day 1 心态
- 永远保持创业第一天的心态，抵抗官僚化和流程僵化
- 快速决策：大多数决策是双向门（可逆的），不需要完美信息就可以行动
- 用 70% 的信息做决策，等到 90% 时你已经太慢了

### 客户至上（Customer Obsession）
- 一切从客户需求出发，逆向工作（Working Backwards）
- 在开始写代码之前，先写新闻稿和 FAQ（PR/FAQ 方法）

### 飞轮效应（Flywheel）
- 识别业务中的增强回路

## Decision Framework
### 当团队提出新想法时：
1. 这解决了什么客户问题？
2. 市场有多大？
3. 我们有独特优势吗？
4. 写出 PR/FAQ

## 文档存放
你产出的所有文档存放在 `docs/ceo/` 目录下。

## Output Format
当被咨询时，你应该：
1. 先明确客户是谁，问题是什么
2. 给出战略判断和优先级建议
3. 识别关键风险和不可逆决策
4. 提出可执行的下一步
```

**关键设计点（我们可以直接学）**：

| 设计 | 我们现状 | 差距 |
|---|---|---|
| **YAML frontmatter** 声明 name/description/model | 我们职责卡是纯 Markdown | 它有元数据，能被程序自动索引 |
| **`description` 写明「什么时候用我」** | 我们写了「擅长什么」 | 它写的是触发条件，更实用 |
| **`Persona` 用真实人物思维模型** | 我们是「技术部主管」泛称 | 具名思维模型质量更高 |
| **`Output Format` 规定输出结构** | 我们有「结论：」开头 | 它更细（4 步） |
| **`文档存放` 指定产出目录** | 我们有规矩一（一个项目一个文件夹） | 等价 |
| 14 个角色覆盖完整公司职能 | 我们 8 位（1 人 + 7 AI） | 职能覆盖方向不同 |

**引擎**：默认 Claude Code，也支持 Codex CLI。

**不支持手机** —— 明确写了 macOS / Windows WSL。

    ├── create_task.py        派活
    ├── file_ops.py           文件操作
    ├── find_skill.py         找技能
    ├── learn_skill.py        学技能
    ├── run_claude_code.py    跑 Claude Code
    └── send_message.py       ★ 发消息
```

**最关键的发现：它有 `send_message.py` 和 `comm/` 目录。**

**这正是我们缺的那一环。** 我们的核心约束是「AI 之间发不了消息，必须人传话」——
这个项目**把发消息做成了工具**，AI 自己调 `send_message` 就能给别的 AI 发。

**它怎么做到的**：因为它是**单一程序**（Python 后端），所有 agent 都是它自己起的进程/线程，
消息传递就是程序内部的函数调用。**根本不需要跨 App 通信。**

**这就是根本差异**：

| | ai-sim-company | 我们 |
|---|---|---|
| Agent 是什么 | 程序内部的对象 | **真实的独立 App** |
| 消息传递 | 内部函数调用 | **受 Android 沙箱限制** |
| 通信难度 | 零 | **高（这是我们的核心痛点）** |
| 真实性 | 模拟（LLM 扮演） | **真实（真的在用 ChatGPT、千问）** |

**两条路线的本质区别**：

> **它模拟一家公司** —— 所有员工都是它自己起的 LLM 实例，通信随便做。
> **我们经营一家公司** —— 员工是真实的第三方 App，通信受系统限制。

**我们更真，它更简单。**

**其他亮点**：

| 特性 | 说明 |
|---|---|
| **时钟控制** | 暂停、单步推进（Play / Step） |
| **经济系统** | 现金流、每日 token 预算、RPM 限速 |
| **组织架构** | CEO → HR → 产品经理 → 工程师/设计师，自发生长 |
| **技能池** | 可分享 / 作用域 / 版本化 |
| **MCP 支持** | 外部 MCP server 供全员使用 |
| **实时看板** | WebSocket 推送日志、任务、现金流 |

## 七、能直接抄的四件事

### 1. 角色定义加 YAML frontmatter（成本极低，收益高）

Autonomous-Company 的格式：

```markdown
---
name: ceo-bezos
description: "公司 CEO。当需要评估新产品想法、商业模式、重大战略选择时使用。"
model: inherit
---

# CEO Agent

## Role
## Persona
## Core Principles
## Decision Framework
## Communication Style
## 文档存放
## Output Format
```

**我们的职责卡改进点**：

| 现在 | 改进 |
|---|---|
| 纯 Markdown，无元数据 | 加 YAML frontmatter |
| 写「擅长什么」 | 改写「**什么时候用我**」（触发条件） |
| 泛称「技术部主管」 | 考虑具名思维模型（如「DHH 式全栈」） |

### 2. `description` 写成「触发条件」

**它写的**：
> 当需要评估新产品/功能想法、商业模式和定价方向、重大战略选择、资源分配和优先级排序时使用。

**我们写的**：
> 擅长：写代码、技术方案、逻辑推理

**差别**：它告诉「**什么时候该找我**」，我们只说了「我会什么」。前者能直接用于派活决策。

### 3. 角色用真实人物思维模型

`ceo-bezos` / `critic-munger` / `qa-bach` —— **具名思维模型**比「XX 部主管」更有行为约束力。

LLM 看到「Bezos 思维模型」会自动调用那套决策框架（Day 1 心态、双向门、PR/FAQ）。

**这比写「你要有战略眼光」有效得多。**

### 4. 加一个实时看板

`ai-sim-company` 用 WebSocket 推日志、任务、现金流。
我们现在是文件式的（去文件夹里翻）。

**这个能补，而且不依赖 Android 限制。** 简单做法：一个本地 HTML 页面，定时读文件刷新。

## 八、结论

> **有轮子，而且不少。但绝大多数是「桌面/服务器/Web 端」，手机原生环境的极少。**
>
> **最像我们的是 `MaxMiksa/Autonomous-Company`（3,199 星，MIT 许可）** ——
> 14 个角色定义写得很好，**角色定义的格式可以立刻抄**。
>
> **`shiyi25928988/ai-sim-company` 架构最接近**（有 send_message、有组织架构、有经济系统），
> 但它是「模拟公司」（AI 扮演员工），我们是「经营公司」（真实 App 当员工）。
>
> **没有任何项目做我们这条路** —— 多个独立 Android App 当 AI 员工 + 文件系统协作 + 真 root。
> **我们这条路更难，但也更真。**
