===== 请帮我看一个项目，直接给批评，不用客气 =====

【背景】
一个人用手机文件夹管理 8 个 AI 员工，模拟一家公司。
结构是：6 个房间（办公区/项目区/会议室/档案室/工具库/制度区）+ 8 个工位 + 21 条规矩。
现在 265 个文件，228 个 markdown，25 MB。

8 个员工：本人（董事长兼秘书，唯一能传话）、总经理 DSH（能读全部）、
以及 ChatGPT / 千问 / 大肥鱼 / 豆包 / Grok / DSH分身（各管一个部门）。

【21 条规矩里最关键的几条】
- 规矩八：DSH 读对话后负责记录 + 实时更新
- 规矩十九：项目完成必须归档 + 清外围
- 规矩二十一：非作者交叉验收
- 规矩二十二：接任务必须先全网学习再动手

【根本问题】
这 5 个第三方 AI（ChatGPT/千问/豆包/Grok/DeepSeek）都是独立手机 App：
- 它们之间没有 API 互通
- 不能主动拉取消息
- 各自活在自己的对话框里，看不到别人说了什么
- 所以【所有信息传递都靠董事长手动复制粘贴】

这是公司的根本瓶颈。每天大量时间花在"复制→切 App→粘贴→切回来"。

【已实测验证的技术事实（不是设想）】
可行：
- root 读取其他 App 的 SQLite 数据库：ChatGPT 9060 条 / 千问 452 条 / DeepSeek 649 条，都能读
- 向其他 App 发送消息：ADB 键盘注入 + UI 自动化，中英文都通（装了 ADBKeyBoard 输入法）
- 检测前台 App、启动任意 App、dump UI 结构（4410 个元素）

不可行：
- 让第三方 AI 主动收消息（没有这种接口）
- FIFO/管道实时唤醒（/sdcard 是 FUSE 不支持 mkfifo）
- input text 直接输中文（Android 限制）

【已经做过的尝试】
第一版：做了 4 个分散面板（公司总览/办公区/项目区/规矩体检）
→ 被驳回，用户说："我要的不是这种！我要一个集合体，而不是分散成好几个插件"

第二版（当前）：改成一个入口，进去是"门厅"，门厅有 6 个房间入口，点进去看细节，能回门厅。
→ 结构对了，但仍是"看板"：能看到公司状态，不能派活、不能收结果、不能自动同步。

【想做成什么样】
一个软件，进去就是整个公司；派活、收结果、归档，全在里面完成。

理想工作流：
早上打开 → 看到昨天谁说了什么、有什么待办 → 定方向 → 点"派活" →
自动投递到各 AI App → 自动监测谁答完了 → DSH 自动读回复、对比、写进项目文档 →
人看结论拍板 → 记录成会议纪要 → 项目完成一键归档打 ZIP 清外围工位回空。

能力分 5 层：
L1 看（状态可视化）✅ 刚做完
L2 派（一键发到各 AI）技术验证过，未集成
L3 收（自动检测谁回完了）技术验证过，未集成
L4 记（自动更新文档进度）未做
L5 管（规矩体检、自动归档、交叉验收）部分做了

【请你回答这 6 个问题，要尖锐的批评，不要鼓励】

Q1. 架构：把"公司"建模成软件，应该以什么为核心实体？
    我们按"房间"组织，但会不会应该按"项目"或"人"或"事件流"？
    有成熟的组织建模范式可借吗？

Q2. 通信（最关键）：5 个第三方 AI 不能主动收消息，只能 UI 注入推送。
    在这个约束下：
    - 有比"ADB 注入 + 读数据库"更好的方案吗？
    - 是否该放弃这些第三方 AI，改用能调 API 的模型（直接起多个 agent）？
    - 如果保留（用户用很久了、有历史对话），代价是什么？

Q3. 状态一致性：公司状态同时存在文件系统（265 个 md）、各 AI 数据库、软件内部 SQLite。
    三份怎么保证一致？谁是唯一真相？冲突听谁的？

Q4. 规矩可执行化：21 条规矩大多是"人的约定"（如交叉验收、通用修复不打补丁）。
    哪些真能机器执行？哪些必须留给人？
    强行自动化会不会产生"假通过"？

Q5. 最小可行路径：如果只能做一件事证明方向对，该做哪件？
    我们倾向 L2 派活（因为它是瓶颈）。对吗？

Q6. 该不该继续：坦白说，这个方向值得做吗？
    还是说"让 AI 之间通信"本身就是在对抗设计？
    有没有更简单的做法（比如全部换成一个多 agent 框架）？

【我们最担心的】
1. 做成花架子：界面好看，但公司运转还是靠人
2. 技术债：ADB 注入很脆弱（App 改版就失效）
3. 过度工程：为了"像公司"做一堆没人用的功能
4. 根本方向错：也许"AI 公司"这个隐喻本身就是限制

【技术栈】
OnePlus PLK110，Android 17，arm64，15GB RAM
承载 App：DSH-Go 1.1.0（DeepSeek Harness 手机版），proot Ubuntu 24.04
插件：$DSH_HOME/dsh-go/plugins/ 下的 npm 包，package.json 的 dshGo 清单声明界面
插件上限：面板 32KiB / 120 组件 / 8 层
root：KernelSU

请直接给批评意见。
