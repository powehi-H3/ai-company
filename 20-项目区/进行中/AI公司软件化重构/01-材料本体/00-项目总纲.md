### 1.3 文件夹方案的 6 个根缺点

| # | 缺点 | 具体表现 |
|---|---|---|
| 1 | **只能看不能操作** | 改东西要进文件管理器→找文件→编辑 |

**一句话：文件夹只适合「存放文件」，不适合「作为公司的操作界面」。**

## 三、硬限制（物理事实，不能假装突破）

### 3.1 能自动化的

| 环节 | 怎么做到 |
|---|---|
| 读各 AI 的回复 | 有 root，能读数据库 |
| **发现「它答完了」** | 监测数据库有没有新内容 |
| 生成派活单 / 汇总分析 | DSH 自己做 |
| 主体 ↔ 分身通信 | 已验证可行（`/sdcard` 共享区） |

### 3.2 ~~做不到的~~ → **已修正：能做，但有难度**

> **董事长 2026-11-16 纠正：「其实这个可以，你们有 root 可以操控我的手机」**
> **实测确认董事长是对的。** 详见 `01-地基验证报告-root自动化.md`

| 环节 | 原判断 | 实测结论 |
|---|---|---|
| 把文字送进 ChatGPT 输入框 | ❌ 做不到 | ✅ **`input text` 可以** |
| 自动点「发送」 | ❌ 做不到 | ✅ **`input tap` / `keyevent 66` 可以** |
| 读取界面找控件 | ❌ 做不到 | ✅ **`uiautomator dump` 可以**（实测 4,410 元素） |
| 启动目标 App | ❌ 做不到 | ✅ **`monkey` / `am start` 可以**（实测切到 ChatGPT） |
| 让它们主动来读消息 | ❌ 做不到 | ❌ **仍然做不到**（这是物理限制） |

**真实困难不是「能不能」，是「稳不稳」：**
1. 界面加载时机不确定（ChatGPT 启动 4 秒还停在启动页，只有 110 元素）
2. 5 个 App 界面结构完全不同，要各写适配器
3. App 更新后适配器会失效，要能自愈

**所以：「你发一次」这个动作永远要你按，但后面的全自动。**

### 3.3 一个必须承认的现实

> **5 个 AI（ChatGPT/千问/大肥鱼/豆包/Grok）是「被动单向」的。**
> 董事长说得对：「虽然不能反向读取，但是我们能读取它们，就相当于一个被动单向的任务协作 AI」。
>
> **这不是缺陷，是架构的物理事实。软件要围绕它设计，不是假装能突破。**

## 四、目标形态

### 4.1 核心转变

```
现在：文件夹当数据库（265 个文件散着）
        ↓
改成：SQLite 数据库当后端 + 原生界面当前端
```

**文件夹**不废除，但只留：
- 长文档（规则、知识库、设计稿）
- 归档 ZIP

**数据库**存：
- 员工 / 项目 / 任务 / 规矩 / 消息 的状态与索引

### 4.2 界面形态：**装进 DSH App 的原生面板**

**为什么不是独立 APK：**

| 方案 | 可行性 | 代价 |
|---|---|---|
| 独立 APK | 能做到 | 要写 Kotlin/Flutter、打包签名、每次改动重装；**要从零重实现读数据库、root、AI 调用** |
| **DSH App 原生面板** | ✅ **现在就能做** | 不打包、改完刷新就生效、**直接能用 DSH 全部能力** |

> **「做成软件」的实质是「有一个操作界面」，不是「一定要独立 APK」。**

**插件能力（已实测确认）：**

| 项 | 内容 |
|---|---|
| 组件 | 15 种：`stack`/`text`/`metric`/`chart`/`compare`/`steps`/`callout`/`list`/`keyValue`/`progress`/`table`/`actions`/`options`/`confirm`/`image` |
| 插槽 | `composer.strip`（输入框胶囊）/ `composer.actions` / `message.actions` / `panels` |
| 呈现 | `page`（整页）或 `sheet`（弹层） |
| 能力 | `insert`（填输入框 ≤2000 字，**绝不自动发送**）/ `toast` / `copy` / `link` / `open` / `command` |
| 异步 | `pending` + `result`（≤60 秒，每插件最多 2 个并行） |
| 限制 | 面板 32 KiB / 120 组件 / 8 层 |

## 五、三个功能怎么落

### 功能 1：一键整包任务（最优先，最简单）

**现在**：开场白 + 任务话术分两次发，共 8 次复制。

**改成**：数据库存模板，界面点一下生成完整文字，**复制一次**。

```
【项目协作说明】
（固定开场白，从模板表取）

【本次任务】
（任务描述）

【要你做什么】
【输出格式】用「结论：」开头
【验收标准】
```

**收益**：8 次 → 1 次。

### 功能 2：自动监测谁答完了（最省力）

**现在**：你挨个去看。

**改成**：定时读各 AI 数据库写进 `replies` 表：

```sql
SELECT ai_name, COUNT(*) AS new_count, MAX(msg_time) AS last_time
FROM replies WHERE seen = 0 GROUP BY ai_name;
```

**界面**：

```
ChatGPT  ● 新 3 条 (2 分钟前)
千问     ● 新 5 条 (8 分钟前)
DeepSeek ○ 无新内容
豆包     ⛔ 读不到
```

**收益**：不用挨个看。

### 功能 4（新增）：自动投递 ★★★ 最高价值

**董事长纠正后才发现的可行功能。**

```
启动 App → 等加载 → dump 找输入框 → tap 点击 → input text 打字
→ 校验文字 → 点发送 → dump 确认已发
```

**价值：直接消灭 8 次复制粘贴。**

| 档 | 内容 | 风险 |
|---|---|---|
| 保守 | 只填好，不发送 | 极低 |
| 半自动 | 填好 + 高亮，你点发送 | 低 |
| 全自动 | 填 + 发 + 读回复 | 中（要授权） |

### 功能 5（新增）：自动读取回复

发送后轮询 dump 界面读回复。和功能 2（读数据库）互为备份。

### 功能 3：自动汇总 + 生成分发

**现在**：你说「同步一下」，我汇总，你再逐条分派。

**改成**：你说「出结果」，我自动：
1. 跑同步
2. 读新回复
3. 对比分析
4. 写回数据库
5. **界面直接列出 4 份可复制的分工**

**收益**：少想一步，直接复制。

**FIFO 的教训**：没先验证可行性就动手，试了三次才发现 `/sdcard` 不支持 `mkfifo`、toybox 不支持两位数 fd。

**这次先验证地基。地基不成立，后面全白搭。**

## 七、第 0 期：地基验证（半天）

### 要验证什么

| # | 验证项 | 判断标准 |
|---|---|---|
| V1 | 能否直接读 ChatGPT 私有数据库 | `/data/data/com.openai.chatgpt/databases/` 可读且能解析 |
| V2 | 能否读千问 | 同上 |
| V3 | 能否读 DeepSeek | 同上 |
| V4 | 数据库是否是 WAL 模式（要一起拷 -wal） | 有 `-wal` 文件就要特殊处理 |
| V5 | 读取是否被 App 加密 | 能读到明文表结构 |
| V6 | 能否判断「有新消息」 | 有时间戳或 rowid 可比较 |
| V7 | 分身体系下是否也能读（user 999 的 App 数据） | 视需要 |

### 判定

| 结果 | 后续 |
|---|---|
| V1~V6 全过 | 功能 2 可行，按计划做 |
| 部分过 | 只对能读的 AI 做监测，其余手动 |
| 全不过 | **功能 2 放弃**，只做功能 1 + 3（仍然省力） |

## 八、红线（绝对不能做）

| 红线 | 原因 |
|---|---|
| ❌ 做独立 APK | 成本极高，且要重从零实现所有能力 |
| ❌ 用无障碍/ADB 自动点击其他 App | 不稳定、有风险、违反其他 App 的使用条款 |
| ❌ 自动发送消息 | 插件 API 明确「绝不自动发送」，这是安全底线 |
| ❌ 展示对话原文到界面 | 隐私风险，只显示统计 |
| ❌ 面板里执行 root 命令 | 安全风险 |
| ❌ 放弃文件夹只用数据库 | 长文档不适合塞数据库，两者要并存 |
| ~~❌ 声称「能自动发消息给 ChatGPT」~~ | **这条已作废** —— 董事长纠正：有 root 就能做，见 `01-地基验证报告-root自动化.md` |

## 十二、一句话

> **我们不是「把文件夹做得更好看」，是「把公司从文件夹里搬进数据库和界面」。**
>
> **能做到的：不用挨个看、不用挨个发、不用自己想分工。**
