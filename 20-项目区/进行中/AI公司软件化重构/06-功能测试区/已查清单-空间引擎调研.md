## ★ 意外高相关发现（深挖确认）
- **382quaii/dsh-Layers-Orchestrator** —— DSH 同生态的**多空间编排器**，几乎就是④的现成轮子：
  - `spaceRouter.js`：多空间路由（每空间一条 FIFO 链、懒加载、错误码）
  - `federation.js`：全局大标签联邦（同名标签跨空间合并为一个全局节点）
  - `dedupe.js`：跨空间内容去重（content_hash 认领）
  - `transfer.js`：跨空间迁移（隐私扫描、grace 期）
  - `consent.js`：显式授权闸门（一次性 token、TTL、单次消费）
- **但三个硬约束**：
  1. 它是 `dsh-layers-hippocampus`（海马体记忆系统）的调度层，依赖那套体系；
  2. 工作区本地包（`link:` 安装），依赖 Windows 路径，未发布 npm，插件市场看不到；
  3. README 明确"不会安装进任何 DSH profile，不会改动运行中宿主"——是别人的工程，状态未安装。
- 判断：**它解决的是"记忆空间联邦"，我们要的是"项目多维度俯瞰"，问题域不同**。可借鉴设计（尤其"同名标签联邦=跨空间同一实体合并"和"授权闸门"），但不宜直接搬。

## 综合判断（供决策，未写码）
④不该做成"通用画布应用"（red flag：造没人用的结构）。真正贴合我们数据的 ④ 最小形态：
- 数据源用现成的③关系图（144节点/259边）+ ②事件流（133事件）——已经是"多维度"了
- "多空间" = 给现有数据切几个**视角切片**（项目维 / AI维 / 时间维 / 产出维），不是造新文件夹
- "叠层" = 在同一俯瞰上叠加不同维度（如先看项目→叠上参与AI→叠上事件流时间轴）
- "穿透" = 从俯瞰节点点进 → 原始文件/对话/产出（我们已有 `/file`、`/list` 接口）
- "俯瞰" = 一张图/Markdown 索引，能 10 秒看清一个项目全貌
