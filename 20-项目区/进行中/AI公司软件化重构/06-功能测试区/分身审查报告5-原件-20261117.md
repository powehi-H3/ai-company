## P0

### P0-1 `/file` 任意文件读取（路径穿越 + 越权读）
- **位置**：`lib/index.js` L435-L440
- **证据**：
  ```js
  '/file': async (q) => {
    const p = q?.path
    if (!p || !p.includes('AI公司')) return { ok: false, reason: 'path rejected' }
    const text = await readText(p, 60000)     // L438：直接把外部传入路径交给 readFile
    return { ok: true, path: p, text }
  },
  ```
  `readText`（L28-L33）内部是裸的 `fsp.readFile(p, 'utf8')`，不做任何规范化。
- **问题**：唯一校验是 `p.includes('AI公司')` 字符串包含。只要路径串里出现「AI公司」四字即可读任意文件，例如
  `path=/storage/emulated/0/AI专用文件夹/AI公司/../../../../etc/hosts`
  或 `path=/AI公司/../../../../proc/self/environ`（`/AI公司` 目录不存在也无所谓，`readFile` 按规范化后的真实路径打开）。
  同文件里的 `resolvePoolFile`（L487-L495）却做了「`.md` 后缀 + 拒 `..` + 拒绝对路径 + 白名单文件名 + `startsWith(root)`」五重防护——说明作者清楚要防穿越，唯独这条只读路由漏了。
- **改法**：抽一个统一的 `resolveInsideRoot(p, { exts, names })`，`/file`、`/list`、`resolvePoolFile` 三处共用：
  ```js
  const abs = path.resolve(root, p)
  if (!abs.startsWith(root + path.sep)) return null
  ```
  客户端 `peekNode` 改为传相对路径，由后端解析（见 P2-5）。
- **降档说明**：若 webServer 仅回环，降 P1；但代码层这是明确漏洞，按 P0 记。

### P0-2 读改写用截断后的文本写回 → 静默丢失文件尾部（数据破坏）
- **位置**：`lib/index.js` L28-L33（`readText` 默认 `max = 200000`）→ L526（apply 读）→ L533-L535（写回）
- **证据**：
  ```js
  async function readText(p, max = 200000) {
    const s = await fsp.readFile(p, 'utf8')
    return s.length > max ? s.slice(0, max) : s     // L31：静默截断，不报错
  }
  ```
  ```js
  // apply 分支
  const text = await readText(abs)                   // L526：未传 max，吃默认 200000
  const r = applyStatusChange(text, q.id, q.toStatus)
  ...
  const tmp = abs + '.tmp'
  await fsp.writeFile(tmp, r.text, 'utf8')           // L534：把"截断后的文本"整份写回
  await fsp.rename(tmp, abs)                         // L535
  ```
- **问题**：`readText` 是给**只读展示**设计的（`/file` 传 60000、进度解析传 12000），但 apply 复用了它且未传 `max`。一旦问题池文件超过 200 000 字符（`01-建议.md`/`02-问题.md` 长期累积完全可能），链路是：
  1. 目标 id 在前 200 KB 内 → `detectSection` 能找到 → preview 通过；
  2. apply 读到同样被截断的 200 KB；
  3. `applyStatusChange` 在截断文本上移动一行，返回「成功」；
  4. **把 200 KB 写回，原文件 200 KB 之后的所有条目永久消失**，且接口返回 `ok:true`、审计记 `ALLOWED`。

  这是**静默数据丢失**，比直接报错危险得多。更隐蔽的是 `readText` 的 `catch { return '' }`（L32）：读失败返回空串而非抛错，虽然当前会因 `findIndex` 返回 -1 被拦下，但这种「失败当空」的约定让任何上层误用都变成静默破坏。
- **改法**：
  1. **读写分离**：apply 必须用**不截断**的读（`await fsp.readFile(abs, 'utf8')`，或 `readText(abs, Infinity)` 并显式声明）；
  2. `readText` 截断时至少返回标记（如 `{ text, truncated: true }`），凡「要写回」的调用点遇到 `truncated` 直接拒绝并报错；
  3. `catch` 分支返回 `null` 并让调用方区分「空文件」与「读失败」，不要把异常吞成 `''`。

## P1

### P1-1 「授权闸门」无真实授权主体，写入可被任意请求方自行完成
- **位置**：`lib/index.js` L499-L510（preview 签发）、L513-L538（apply 校验）；`lib/spaces.js` L70-L84
- **证据**：
  ```js
  const token = issueConsent(action, bind)          // index.js L508：对任何请求方无条件签发
  ...
  const gate = checkConsent(q.token, action, bind)  // index.js L516：只验票，不验"谁"
  ```
- **问题**：所谓「授权闸门」实质只是「两步确认」——token 由服务端对**任何**请求方无条件签发。任何能访问 `/ai-company/intervene` 的客户端（本机其他进程；若端口暴露则局域网任意主机）都能自己 preview 拿票、自己 apply 改文件。风险分级（`riskOf`）只拦「动作类型」，没拦「操作主体」。真正的人工批准环节不存在。
- **改法**：二选一并写进文档——
  - 若语义就是「用户点确认即授权」：必须保证 webServer 仅回环 + 写接口加同源校验/CSRF 挑战；
  - 若要真「授权」：preview 后把票据交可信方（如 `handoff` 让用户确认）审批，再由后端签发短时 token。
- **降档说明**：仅回环可达时降 P2。

### P1-2 授权 token 用非密码学随机源
- **位置**：`lib/spaces.js` L71
- **证据**：
  ```js
  const token = 'consent_' + Math.random().toString(36).slice(2) + Date.now().toString(36)
  ```
- **问题**：`Math.random()` 是 V8 xorshift128+，可预测；且拼接了可观测的 `Date.now()`。作为「授权令牌」不应使用非安全随机。当前有 60s TTL + 单次消费 + 进程内 Map 兜底，可利用性有限，但这是原则性缺陷。
- **改法**：`import crypto from 'node:crypto'`，用 `crypto.randomUUID()` 或 `crypto.randomBytes(16).toString('hex')`。

### P1-3 编号匹配不锚定行首 → 可搬错行、破坏正文
- **位置**：`lib/spaces.js` L197（`applyStatusChange`）、L178（`detectSection` 同样）
- **证据**：
  ```js
  const idx = lines.findIndex(l => l.includes(`[${id}]`))   // L197
  ...
  if (l.includes(`[${id}]`)) return cur || '未知'            // L178
  ```
  而 `parseIssues`（index.js L47-L48）只认 `^-\s*\[` 开头的条目行。
- **问题**：全行 `includes` 不锚定，导致
  1. **误搬正文**：若正文中有一行引用 `[REQ-001]`（如「详见 [REQ-001] 的结论」）且排在真正条目之前，`findIndex` 命中的是正文行 → 被 `splice` 掉、重新拼成 `- 详见 [REQ-001] 的结论` 插进目标区块，**原条目原地不动、正文被毁**；
  2. **重复编号**：同一文件出现两条同编号时只搬第一处，而前端展示的可能是第二条，出现「点了 A、改了 B」。
- **改法**：与 `parseIssues` 对齐锚定：`l.trim().startsWith('- [' + id + ']')`；移动前统计命中数，`>1` 时拒绝并报「编号重复，请人工确认」，不要静默取第一个。

### P1-4 `/consent` 公开、无条件签发令牌（未接线但已暴露）
- **位置**：`lib/index.js` L455-L465
- **证据**：
  ```js
  if (q?.issue) {
    const token = issueConsent(q.action || 'write', { target: q.target || '' })
    return { ok: true, token, hint: '30秒内有效，单次消费' }   // L458
  }
  ```
- **问题**：任何人 GET `/ai-company/consent?issue=1` 即得令牌，零鉴权。当前签发的 payload 是 `{target}`、`/intervene` 用的是 `{id,file,toStatus}`，二者 `JSON.stringify` 不同 → **目前打不进 apply**（未形成可利用链），但这是一个「授权闸门形同虚设」的活体接口，一旦接线立即越权。
  另：`hint` 写「30秒内有效」，实际 `ttlMs` 默认 **60000**（60 秒），**文案与实现不符**。
- **改法**：删除这条未接线路由；授权签发只应在 `/intervene` 的 preview 内、绑定完整 payload、受真实授权主体约束（见 P1-1）。若保留则修正 hint 文案。

### P1-5 原子写 tmp 路径固定 → 并发写丢改动
- **位置**：`lib/index.js` L533-L535
- **证据**：
  ```js
  const tmp = abs + '.tmp'
  await fsp.writeFile(tmp, r.text, 'utf8')
  await fsp.rename(tmp, abs)
  ```
- **问题**：tmp 恒为 `<目标文件>.tmp`。两个不同条目同时 apply **同一份**问题池时，两次写落同一 tmp，`writeFile`/`rename` 之间有 await 让出点，交错后最终文件只含其中一次改动——**另一次改动静默丢失**，两条都返回 `ok:true`。用户会看到两个「✅ 已改为」，实际只生效一个。
- **改法**：tmp 用唯一名（`abs + '.' + crypto.randomBytes(4).toString('hex') + '.tmp'`）；对同一 `abs` 加进程内互斥（`Map<abs, Promise>` 串行化）；`finally` 清理残留 tmp（当前崩溃会留下 `.tmp` 垃圾文件）。

### P1-6 审计失败静默，客户端完全不看 `auditErr` → 审计链可断裂
- **位置**：`lib/index.js` L479-L484（吞错）、L536（ALLOWED 审计在写盘之后）；`lib/client.js` L190-L194
- **证据**：
  ```js
  const writeAudit = async (rec) => {
    try { await fsp.appendFile(auditPath, JSON.stringify(rec) + '\n', 'utf8') }
    catch (e) { /* 审计失败不影响主流程 */ return String(e.message || e) }   // L482
    return null
  }
  ```
  ```js
  // client.js 成功分支，不检查 r.auditErr
  if (r.ok) { setMsg('✅ 已改为「' + gate.toStatus + '」'); setGate(null); onChanged && onChanged() }
  ```
- **问题**：审计是 append-only 安全链路，但 ① 写失败只回传字段、主流程照常成功；② 客户端 **preview 与 apply 成功分支都不读 `r.auditErr`**。结果：「文件改了、审计没记、用户毫无感知」。且 `06-功能测试区/` 目录不存在时 `appendFile` 直接 ENOENT（不创建目录），这个失败路径完全无声。
- **改法**：改为「先写审计、后改文件」，审计写失败即拒绝 apply；至少客户端对 `auditErr` 明确红字告警；启动时 `mkdir -p` 审计目录。

### P1-7 `buildOverview` 丢弃 `ref` → 上帝视角「穿透」功能 100% 失效
- **位置**：`lib/spaces.js` L90（`add` 定义）、L94-L103（调用处）；`lib/client.js` L272-L278（依赖 `n.ref`）
- **证据**：
  ```js
  const add = (id, label, type, space) => nodes.push({ id, label, type, space })   // L90：没有 ref
  ...
  for (const n of data.graphNodes || []) {
    if (n.type === 'chat' || n.type === 'artifact') add(n.id, n.label, n.type, 'knowledge')  // L99：n.ref 被丢弃
  }
  ```
  而 `index.js` L388 明明把 `ref` 读进了 `graphNodes`：
  ```js
  graphNodes.push({ id: n.id, label: n.label, type: n.type, ref: n.ref })
  ```
  客户端 `peekNode` 的第一道判断：
  ```js
  if (!n.ref) { setPeek({ label: n.label, text: '（该节点无穿透引用：' + n.id + '）' }); return }   // client.js L272
  ```
- **问题**：`federate` 输出、`dedupe` 保留的都是 `add` 造出来的对象，`ref` 从头到尾不存在。因此**所有空间节点点下去都只显示「该节点无穿透引用」**，「点节点穿透到原文」这个核心功能完全不可用，且界面上还照常渲染「穿透 ›」提示（L330 同样依赖 `n.ref`，所以连这个标记也不会出现）——用户看到的是「点了没反应」。
- **改法**：`add` 增加第 5 参 `ref`，`knowledge` 分支传 `n.ref`；`federate` 合并同名节点时保留首个非空 `ref`；`buildOverview` 输出后在 `GodView` 里确认 `n.ref` 存在。

## P2

### P2-1 `/list` 的 `dir` 未防穿越，可枚举 root 外 `.md`
- **位置**：`lib/index.js` L441、L408-L429（`listFiles`）

- **问题**：`dir=../../etc` 时 base 落到公司目录外，walk 深度 5，可枚举外部目录的 `.md` 文件名与大小（不含内容，但可配合 P0-1 读内容）。
- **改法**：与 P0-1 共用同一路径约束。

### P2-2 `CONSENTS` Map 无回收，过期 token 常驻
- **位置**：`lib/spaces.js` L69-L84
- **证据**：过期条目仅在 `checkConsent` 命中该 token 时才 `delete`（L78）。
- **问题**：高频 preview 持续累积一次性 token，进程常驻内存只增不减。
- **改法**：签发时顺带清理过期项或设容量上限（`if (CONSENTS.size > 10000) 清过期`）。

### P2-3 `/spaces` 回传空间绝对路径，泄漏宿主布局
- **位置**：`lib/index.js` L449
- **证据**：`space: { id: s.id, zh: s.zh, icon: s.icon, abs: s.abs }`
- **问题**：前端根本用不到 `abs`（穿透走的是自己拼的绝对路径），却把服务器物理路径暴露给浏览器。
- **改法**：只回相对路径。

### P2-4 apply 不重探 fromStatus，preview 承诺可能失真
- **位置**：`lib/index.js` L526-L527
- **证据**：apply 直接 `applyStatusChange(text, q.id, q.toStatus)`，不复用 `detectSection` 校验当前区块。
- **问题**：preview 显示「待处理 → 处理中」，若期间文件被改成「处理中」，apply 仍会把它从「处理中」再搬到「处理中」（原地搬、改变顺序），preview 与实际不符。
- **改法**：apply 前重跑 `detectSection`，与 preview 记录的 fromStatus 比对，不一致或已达标则拒绝并提示「状态已变化，请重新预览」。

### P2-5 客户端硬编码 root 第一候选 + `ref` 未防穿越
- **位置**：`lib/client.js` L271-L278
- **证据**：
  ```js
  let rel = n.ref
  if (rel.startsWith('对话原文/')) rel = '60-工具与备份/知识库/' + rel
  else if (!rel.includes('AI公司/')) rel = '20-项目区/进行中/AI公司软件化重构/' + rel
  const full = '/storage/emulated/0/AI专用文件夹/AI公司/' + rel   // L276
  ```
- **问题**：① 硬编码 `companyRoot()` 的第一个候选，落到第二候选（`/sdcard/...`）的设备上穿透必然读错；② `n.ref` 来自 jsonl、未校验，含 `../../` 会穿越，且正落进 P0-1 的弱校验。
- **改法**：穿透改传相对路径、由后端统一解析（见 P0-1）。

### P2-6 `detectSection` 与 `applyStatusChange` 区块表不一致
- **位置**：`lib/spaces.js` L166-L181 vs L185-L190
- **证据**：`applyStatusChange` 的「已完成」多一条 `'## 三、已完成（留痕，不删除）'`；`detectSection` 没有。且「待处理/处理中」的 `## 一、`/`## 二、` 变体只在 detect 里有、apply 里没有。
- **问题**：两处对「哪些标题属于哪个区块」认定不同步，后续改标题极易出现「preview 能识别、apply 找不到目标区块」的割裂。`startsWith(h)` 也会把 `## 待处理区` 误当 `## 待处理`。
- **改法**：标题表提成单一常量共用；匹配改为精确标题或「标题 + 可选空白/全角括号后缀」。

### P2-7 `force` 刷新会复用进行中的旧扫描
- **位置**：`lib/index.js` L120-L133
- **证据**：
  ```js
  if (!force && COLLECT_CACHE && now - COLLECT_AT < CACHE_TTL) return COLLECT_CACHE
  if (COLLECT_PENDING) return COLLECT_PENDING      // L123：force 也会命中
  ```
- **问题**：改完状态点「刷新」，若恰逢上一轮 collect 未完成，拿到的是**不含本次改动的旧快照**，用户以为没生效。
- **改法**：force 时等待 pending 完成后再重扫，或直接排队新扫描。

### P2-8 `resolvePoolFile` 白名单用 `endsWith`，可被前缀绕过
- **位置**：`lib/index.js` L491
- **证据**：`if (!okNames.some(n => rel.endsWith(n))) return null`
- **问题**：`x00-问题需求池.md`、`我的00-问题需求池.md` 均满足 `endsWith`。危害低（仍限 root 内 `.md`），但白名单意图是「只准这四个精确文件名」。
- **改法**：取 `path.basename(rel)` 后与白名单**全等**比较。

### P2-9 `/audit` 用截断读 + `slice(-50)` → 日志超 200 KB 后看不到最新干预
- **位置**：`lib/index.js` L544-L549
- **证据**：
  ```js
  const lines = (await readText(p)).split('\n').filter(Boolean)   // readText 默认只保留前 200000 字符
  return { ok: true, records: lines.slice(-50).map(...) }
  ```
- **问题**：`readText` 是 `slice(0, max)`，**砍掉的是尾部**。日志超过 200 KB 后，`slice(-50)` 取到的是「前 200 KB 里的最后 50 条」，恰恰看不到最新记录——审计查看功能在关键时刻失真。截断点若落在行中，该行 `JSON.parse` 失败被 `filter(Boolean)` 静默丢弃。
- **改法**：审计读取用流式/尾部读（`tail` 式：读文件尾部 N KB），或干脆不截断；解析失败的行要计数上报而非静默丢弃。

### P2-10 其他低危项
- **`toStatus` 未白名单校验**（`index.js` L495）：非法值要绕到 `applyStatusChange` 的「找不到目标区块」才被拒，且会签发票据。建议 preview 入口就校验 ∈ {待处理, 处理中, 已完成}。
- **`parseIssues` 类型判定顺序**（`index.js` L51-L54）：`/REQ/` 先于 `/BUG/`，`BUG-REQ-001` 这类混合编号会被判成 suggest。建议按 `BUG > OPT > REQ` 或精确前缀判定。
- **`detectSection` 遇到未知区块沿用上一个区块名**（`spaces.js` L174-L178）：条目若在 `## 挂起` 下，`cur` 保持上一次命中的区块，preview 会显示错误的 fromStatus。建议遇到未知 `##` 标题时把 `cur` 重置为 `'未知'`。
- **`applyStatusChange` 丢失原缩进/项目符号**（`spaces.js` L196）：`replace(/^\s*-\s*/, '')` 对 `  - xxx` 会丢缩进、对 `* xxx` 不匹配导致插入后变成 `- * xxx`。建议只剥「行首空白 + `-` + 一个空格」并保留原缩进层级。
- **`dedupe(federate(nodes))` 冗余**（`spaces.js` L105）：`federate` 已按 `type:id` 去重，`dedupe` 的 fallback key `${type}:${id}:${title||''}` 因节点无 `title` 退化为同一 key，属重复劳动；且若将来给节点加 `title` 反而会让 dedupe 比 federate 更松。建议删掉 `dedupe` 或明确其只处理「有 contentHash」的场景。
- **`/audit`、`/timeline` 在 `companyRoot()` 为 null 时**（`index.js` L545、L553）：`path.join(null, ...)` 抛 TypeError → 500；`/timeline` 拼出 `"null/20-..."` 返回误导性的「还没有事件流文件」。建议两处都先判 `!root` 返回明确错误。
- **客户端 `DATA_CACHE` 模块级缓存永不失效**（`client.js` L120-L121）：切 tab 回来不刷新，且是模块级变量、跨实例共享。低危，但会让「刷新」语义混乱。
