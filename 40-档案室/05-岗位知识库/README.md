# 岗位知识库

**这是解决「上下文一断就白做」的核心。**

---

## 一、为什么要有这个柜子

| 问题 | 后果 |
|---|---|
| 新开对话，AI 什么都忘了 | 定位、规矩、项目全要重讲 |
| 上下文太长被压缩 | 细节变成摘要，慢慢走样 |
| 换一个 AI 来干 | 从零开始，白做 |

**所以：把「我是谁、我该懂什么、开工前看什么」写成文件。**
每次开工，AI 先读文件，不靠聊天记忆。

## 三、怎么用（三句话）

1. **新开对话** → 对 DSH 说「进公司，先读开工必读」
   （分身同理：读 `03-工程部-DSH分身/00-开工必读.md`）
2. **接新任务** → DSH 先读 `02-岗位知识.md` 里对应那节
3. **干完** → 有新经验就更新这个知识库（写进 CHANGELOG）

## 四、和"养鱼"思路的关系

YG 的想法：像养鱼一样把 DSH 培养成特定性格，一个项目配几个分身，各专一门。

**业界确实这么干**（联网查到）：
- `opencorp`：给 AI 配「角色 + 技能 + 工具 + 记忆」，记忆跨会话保留
- `crewai`：每个 Agent 有明确的 role 和 task 配置
- `dev-os-starter-pack`：一个 Agent 一个任务、独立审核、全程留记录

**我们现在先不搞多个分身，从「1 个 DSH + 1 套岗位知识」试点。**
跑通了，再复制到别的岗位。
