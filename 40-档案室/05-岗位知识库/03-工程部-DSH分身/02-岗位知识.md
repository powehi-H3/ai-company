## 二、Android 多用户机制（必须懂）

### uid 换算

```
uid = userId * 100000 + appId
主体: 0   * 100000 + 10458 = 10458
分身: 999 * 100000 + 10458 = 99910458
```

### 存储隔离

| 用户 | 自己的存储 | 能看到别人的吗 |
|---|---|---|
| user 0（主体） | `/storage/emulated/0` | 能看 `/storage/emulated/999` |
| user 999（分身） | `/storage/emulated/999` | 能看 `/storage/emulated/0`（读） |

**注意**：分身的 `/sdcard` 是 `/storage/emulated/999`，**不是** `/storage/emulated/0`。
所以在分身里 `cat /sdcard/AI专用文件夹/...` 会报 No such file or directory，
但 `cat /storage/emulated/0/AI专用文件夹/...` 能读到。

### 写权限

| 目标 | 无 root | 有 root |
|---|---|---|
| 主体存储 `/storage/emulated/0/...` | 不能（Permission denied） | 能写，属主变成 `u0_a318` |
| 自己的存储 `/storage/emulated/999/...` | 能写 | 能写 |

## 三、root 通道用法

### 基本用法

```sh
python3 ~/tools/rootc.py 'id'                    # 单条命令
python3 ~/tools/rootc.py --info                  # 看自己是谁
python3 ~/tools/rootc.py --role                  # 只输出 primary / clone
python3 ~/tools/rootc.py --on                    # 开本实例
python3 ~/tools/rootc.py --off                   # 关本实例
```

### 写文件的正确姿势

命令通道**会把换行压平**，所以用 heredoc 写多行文件会坏。正确做法：

```sh
# 方法1：先在能写的地方写好，再 root 复制
#   先写 /storage/emulated/0/rootd-out/tmp.md（分身无 root 也能写这里吗？不能，走方法2）
# 方法2：分身在本地写好后，用 root 复制过去
python3 ~/tools/rootc.py 'cp /本地已写好的文件 /目标/路径.md'

# 方法3：单行内容用 printf
python3 ~/tools/rootc.py 'printf "%s\n" "第一行" "第二行" > /目标/路径.md'
```

### 已知限制

| 限制 | 说明 |
|---|---|
| `ksu.exec`（WebUI 里）只返回最后一行 | 每实例要单独调一次，不能用 for 循环 |
| 命令通道压平换行 | 多行脚本必须先写成文件 |
| 默认超时 130 秒 | 长任务要分批 |
| 守护没跑时客户端快速失败 | 心跳超 20 秒判定没跑 |

## 四、绝对不许碰的（血泪教训）

### 会杀死守护的操作

以下四条**全部禁止**：

1. `source /data/adb/modules/rootd_keeper/common/rootd-priv.sh`
2. `kill -9` 守护 pid
3. `nohup sh rootd-priv.sh &`
4. `timeout 6 sh rootd-priv.sh`

**原因**：命令是由守护 fork 的子进程执行的，和守护同进程组。
任何按进程组发信号的操作（kill、timeout、进程组清理）都会连带杀死守护。

**正确做法**：

```sh
# 只读查状态
cat /data/adb/rootd_keeper/state/rootd.pid
ps -A -o PID,PPID,ARGS
cat /storage/emulated/0/rootd-out/heartbeat

# 要重启，用 init
setprop ctl.stop rootd-priv
setprop ctl.start rootd-priv

# 最稳：让董事长点模块卡片的「执行」按钮
```

### 会误判的测试方法

| 方法 | 为什么错 | 正确做法 |
|---|---|---|
| `mkdir -p X && echo OK` 测写权限 | `-p` 会创建整条路径并返回成功 | 先 `ls -d` 确认父目录存在 |
| `ps` 加 grep 脚本名判断进程 | 匹配 ARGS 全文，会命中命令行文本 | 用 awk 精确匹配 argv[1] |
| 只看 `id` 判断有没有 root | proot 里 id 显示 uid=0 是假的 | 看 CapEff 和 SELinux context |

## 五、KernelSU 模块开发要点

### 目录结构

```
/data/adb/modules/<模块id>/
  module.prop          模块信息
  customize.sh         安装时执行（被 source，不是执行）
  service.sh           开机服务
  post-fs-data.sh      更早的启动阶段
  boot-completed.sh    启动完成后
  action.sh            模块卡片「执行」按钮
  uninstall.sh         卸载
  initrc/rootd.rc      init 服务定义
  common/              公共脚本
  webroot/index.html   WebUI
```

### 关键坑

| 坑 | 说明 |
|---|---|
| **init 启动的脚本没有 PATH** | 必须显式 export PATH，否则 basename/date/stat 全失效。这是最致命的静默失败根因 |
| **状态目录不能放模块目录里** | 模块升级/卸载会删掉整个目录，状态要放 `/data/adb/<id>/state` |
| **webroot 权限别自己设** | KSU 安装时自动设权限和 SELinux 上下文，自己改会出问题 |
| **init 服务要 oneshot** | 否则进程退出后 init 会自动重启，变成重启风暴 |

### 调试方法

```sh
# 看守护日志
tail -50 /storage/emulated/0/rootd-out/rootd.log

# 看进程
ps -A -o PID,PPID,ARGS

# 看心跳
cat /storage/emulated/0/rootd-out/heartbeat

# 看实例登记
cat /data/adb/rootd_keeper/state/instances
```

## 五点五、toybox vs GNU：同一个命令行为不同

**这是最坑的一类问题：proot 里能用，真机 root 里不能用。**

| 命令 | proot（GNU） | 真机 root（toybox） |
|---|---|---|
| `setsid -f` | ✅ 支持 | ❌ **不支持**（`setsid: Unknown option 'f'`） |
| `ps -o PID,PPID,ARGS` | ✅ | ✅ 支持，但 `-A` 等组合要注意 |
| `stat -c %u` | ✅ | ✅ |
| `sed -n '1p'` | ✅ | ✅ |
| `flock` | 有 | ✅ `/system/bin/flock -> toybox` |

### 怎么避免踩坑

**在 proot 里测通的命令，到真机 root 里必须重测一遍。**

我因为这个踩了 6 次：每次想用 `setsid` 脱离会话重启守护，都失败，
因为 proot 的 setsid 是 GNU 版（支持 `-f`），真机是 toybox 版（不支持）。

**正确的脱离会话方式**（真机可用）：
```sh
nohup /system/bin/sh 脚本.sh >/dev/null 2>&1 &
```

但注意：`nohup &` 仍继承进程组，如果脚本里有按进程组发信号的操
（如 `setprop ctl.stop`），可能连带影响。**最稳的还是让董事长点「执行」按钮。**

## 五点六、别的方案怎么做的（参考）

详见同目录 `05-参考-DSHGo官方root方案.md`。核心对比：

| 方案 | 起 root 方式 | 通信 | 支持多实例 |
|---|---|---|---|
| **DSH-Go 官方** | `su -c app_process` 起 Java 进程 | 进程 stdin/stdout 二进制帧 | ❌ |
| **dsh-rootd-v4.9.3** | KSU 模块 + service.d | 文件信箱 + watchdog | ❌ |
| **dsh-root-bridge** | KSU 模块 + 单 FIFO | 文件队列 + FIFO 唤醒 | ❌ |
| **我们 rootd_keeper** | KSU 模块 + init 守护 | 文件队列 + 轮询 | ✅ 主体+分身 |

**三条该学的工程纪律**（来自官方方案）：
1. 管道要抽干 stderr —— 不抽干会因缓冲区写满阻塞子进程
2. 超时后整条重建 —— 流已错位，复用必出错
3. 版本不符就拒绝 —— 不做兼容猜测
