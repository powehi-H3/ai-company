## 一、先说结论：为什么大家都用 GitHub

**一句话：GitHub 不只是「放代码的地方」，它是「一群人怎么协作做一件事」的完整工具链。**

普通人理解的 GitHub：网盘，存代码的。
实际上的 GitHub：**代码托管 + 版本管理 + 任务追踪 + 自动测试 + 自动发布 + 文档站 + 社区**，六合一。

## 二、GitHub 到底有哪些功能（逐个说清）

### 2.1 核心：Repository（仓库）

**是什么**：一个项目的所有文件和修改历史，全都存在这里。

**有什么用**：
- 存代码（也存文档、图片、配置，什么都能存）
- **记住每一次修改**（谁改的、什么时候、改了什么、为什么改）
- 任何时候能回到任何一个历史版本

**打个比方**：像一个**带完整录像回放的文件夹**。你随时能看到「三天前这个文件长什么样」。

**三个关键概念**：

| 词 | 意思 | 打个比方 |
|---|---|---|
| **commit** | 一次提交 = 一次存档点 | 游戏存档 |
| **branch**（分支） | 平行的开发线，互不干扰 | 同一本书的不同草稿 |
| **merge**（合并） | 把分支合回主线 | 把草稿并进正本 |

---

### 2.2 Issue（问题单 / 任务单）

**是什么**：一个可以讨论的「待办事项」或「问题报告」。

**有什么用**：
- 用户报 bug
- 提功能建议
- 记录待办
- **每个 Issue 有编号、有状态（开/关）、能评论、能打标签、能指派给人**

**真实例子**：dsh-Go 现在有 **631 个未关闭的 Issue**。这意味着：
- 631 个用户提的问题/建议还在排队
- 每一个都能点进去看细节、看进展

**为什么重要**：**它把「口头反馈」变成了「可追踪的记录」。** 不会丢，不会忘。

---

### 2.3 Pull Request（PR，拉取请求）

**是什么**：**「我改好了，你看看要不要合进去」** 的正式申请。

**这是 GitHub 最核心的协作机制。**

**流程**：
```
1. 你 fork（复制）别人的项目
2. 你在自己的副本里改代码
3. 你提一个 PR：「我修了 XX 问题，请合并」
4. 原作者review（审阅）你的改动
5. 讨论、修改、再讨论
6. 通过 → 合并进主项目
```

**为什么重要**：
- **改了什么一目了然**（逐行对比）
- **可以讨论每一行代码**
- **没通过就不合，主项目不受影响**
- 大项目几千人协作，靠的就是这个

**真实例子**：Linux 内核、React、Vue 这些几千万行代码的项目，全靠 PR 协作。

---

### 2.4 Actions（自动化流水线）

**是什么**：**「代码一提交，自动帮你做一堆事」**。

**这是 GitHub 最被低估的功能。**

**能自动做什么**：

| 场景 | 说明 |
|---|---|
| **自动跑测试** | 每次提交自动编译、跑测试，挂了就通知你 |
| **自动检查代码风格** | 缩进不对、命名不规范，自动挑出来 |
| **自动打包** | 自动编译出 APK / exe / dmg，用户直接下载 |
| **自动发布** | 打 tag 就自动发布到 Release |
| **自动部署网站** | 推到 main 就自动更新网站 |
| **定时任务** | 每天早上 9 点自动跑个脚本 |

**真实例子**（dsh-Go 的 ci.yml 开头注释）：

```yaml
# A PR runs what it touches; a push to main runs everything, which also catches
# whatever the path filters below miss. `CI OK` is the one result to look at.
# External PRs are closed by pr-gate.yml and spend no runner here.
```

翻译：**「PR 只跑它改到的部分；推 main 就跑全套。外部 PR 直接拦掉，不浪费服务器资源。」**

这已经是**很成熟的工程实践**了。

**免费额度**：公开仓库 **完全免费**（每月 2000 分钟私有仓库额度）。

---

### 2.5 Releases（发布页）

**是什么**：给用户下载成品的页面。

**有什么用**：
- 上传编译好的安装包（APK / exe / dmg / zip）
- 写更新日志
- 用户直接下载，**不用懂代码**

**真实场景**：你用 GitHub 装的那些工具，基本都是从这里下载的。

---

### 2.6 Pages（免费网站托管）

**是什么**：**把仓库变成网站，免费。**

**有什么用**：
- 项目官网
- 文档站
- 博客

**免费到什么程度**：静态网站全免费，带 HTTPS，带自定义域名。

---

### 2.7 Star / Fork / Watch（三个社交动作）

| 动作 | 意思 | 为什么做 |
|---|---|---|
| **Star**（星标） | 「我收藏了 / 我觉得好」 | 相当于点赞+收藏。**Star 数是项目的声望** |
| **Fork**（复刻） | 「我复制一份到我的账号下」 | 想改、想基于它做新东西 |
| **Watch**（关注） | 「有动静通知我」 | 关注进展 |

**Star 数的意义**：dsh-Go 有 23,995 星 —— 这是**真实的社会认同**，不是刷的。

---

### 2.8 其他功能

| 功能 | 是什么 | 什么时候用 |
|---|---|---|
| **Projects** | 看板（像 Trello） | 管理任务进度 |
| **Discussions** | 论坛式讨论区 | 答疑、想法交流（比 Issue 更开放） |
| **Wiki** | 项目自带文档区 | 写长篇文档 |
| **Gist** | 单个代码片段分享 | 分享一小段代码 |
| **Codespaces** | 云端开发环境 | 不用本地装环境，浏览器里就能写代码 |
| **Packages** | 包托管 | 发布 npm / Docker 镜像等 |
| **Code Review** | 逐行审阅 | PR 里自动带 |
| **Insights** | 统计分析 | 看谁贡献最多、什么时候最活跃 |

## 三、许可证（License）：这是最容易被忽略、但最重要的一环

**为什么重要**：决定「别人能拿你的代码干什么」。

| 许可证 | 能做什么 | 必须做什么 | 典型项目 |
|---|---|---|---|
| **MIT** | 随便用、改、商用 | 保留版权声明 | React、jQuery、我们参考的 DSH-Go root 代码 |
| **Apache-2.0** | 同上 + 专利授权 | 保留声明 + 标注改动 | Android、Kubernetes |
| **AGPL-3.0** | 能用、能改 | **改了必须开源，连网络服务也算** | **dsh-Go 本体**、MongoDB |
| **GPL-3.0** | 能用、能改 | 分发必须开源 | Linux 内核 |
| **BSD** | 类似 MIT | 保留声明 | FreeBSD、Go 语言 |
| **无许可证** | **默认保留所有权利，别人不能合法使用** | — | 很多新手项目 |

**注意**：**没有 LICENSE 文件 = 别人不能合法用你的代码。** 这是新手最常犯的错。

**真实案例**：
- dsh-Go 本体是 **AGPL-3.0** —— 严格。谁改了拿去做网络服务，必须开源。
- 我们参考的 root 通道代码是 **MIT** —— 宽松。可以随便用。
- 这就是为什么我们能合法地参考那 16 个 .kt 文件。

## 四、为什么大家都在这上面做项目（真实原因）

### 原因 1：它把「协作」的摩擦降到了零

传统协作：
```
你改一版 → 微信发给我 → 我改一版 → 邮件发回去 → 版本乱了 → 谁改了什么不知道
```

GitHub：
```
你推一个分支 → 提 PR → 我逐行看 → 评论 → 你改 → 合并
全过程有记录，谁改了什么清清楚楚
```

### 原因 2：免费，而且免费得很彻底

| 项目 | 免费额度 |
|---|---|
| 公开仓库 | **无限个、无限空间、无限协作人** |
| Actions（自动化） | 公开仓库**完全免费** |
| Pages（网站） | **完全免费**，带 HTTPS |
| Releases（发布） | **无限流量** |
| Issues / PR / Projects | 全免费 |

**一个开源项目可以完全零成本运行。**

### 原因 3：曝光 = 机会

- **2.4 万星的项目，作者会收到工作邀请**
- 招聘方直接看你的 GitHub 贡献记录
- 你的代码被别人用 = 最好的简历

### 原因 4：AI 时代的新理由（这条最重要）

**GitHub 现在是 AI 训练语料的主要来源，也是 AI 工具的主战场：**

| 现象 | 说明 |
|---|---|
| AI 编程助手（Copilot 等） | 训练数据大量来自 GitHub 公开代码 |
| AI 能直接读 GitHub 仓库 | 像我今天这样，用 API 直接取源码分析 |
| 开源 = 被 AI 学习 = 影响未来 | 你不开源，AI 就学不到你的做法 |

**这也是我今天能把你给的链接里的 16 个 .kt 文件全下载下来分析的原因 —— 因为它开源。**

### 原因 5：可信度

| 有 GitHub | 没有 GitHub |
|---|---|
| 「代码在这，你自己看」 | 「相信我，我写的」 |
| 能看到提交历史、谁改的 | 无法验证 |
| 能自己编译验证 | 只能信 |

## 五、它的局限（不是万能）

| 局限 | 说明 |
|---|---|
| **不适合放敏感信息** | 一旦公开，永久留在历史里（就算删了，Fork 过的还有） |
| **不适合大文件** | 单个文件超 100MB 会被拒（要用 Git LFS） |
| **国内访问不稳定** | 有时慢、有时连不上（这就是为什么我们用 `api.github.com` 而不是网页） |
| **学习曲线** | Git 命令对新手不友好（但有图形客户端） |
| **代码 ≠ 能跑** | 很多项目文档差、依赖复杂，克隆下来跑不起来 |
